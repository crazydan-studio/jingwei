注意，演示数据采用静态赋值，不要模拟异步 fetch。

## **一、主页面**

- 以标签形式切换已启用、开发中、已禁用、全部的应用列表
- 应用列表中以卡片形式显示应用名称、图标、激活版本等基本信息，同时提供启用/禁用、版本管理等操作按钮
  - 删除、编辑按钮放在卡片右上角的下拉菜单中
  - 启用/禁用、版本管理、进入应用占据卡片底部整行，并在行内排列

### 1. 应用管理

- 在新增或编辑表单中不能设置状态，也不显示唯一标识、数据库表前缀

### 2. 应用版本管理

- 以抽屉形式实现应用版本管理
- 以列表分页形式显示当前应用的版本
- 支持新建版本
- 在列表中根据版本状态提供查看、删除、发布、编辑、设计、激活、衍生等操作支持
  - 编辑是编辑版本基本信息
  - 设计是在版本开发页面设计功能
- 在新增或编辑表单中不能设置状态

## **二、版本开发页面**

页面整体划分为上下两部分，顶部为 Header，负责显示版本信息和状态并提供编辑、发布、激活等功能按钮，
底部为版本开发区，负责进行应用版本的开发。

版本开发区又分为左右两部分（采用面板分割组件实现），左侧为需求编辑区，负责录入和修改开发需求，
右侧为生成代码编辑区，负责编辑 AI 生成的代码并实时查看预览效果。

### 1. 需求编辑区

- 可随时调整需求内容，或者切换选择不同的 AI 模型
- 在点击生成按钮后，在编辑区上层显示等待遮罩，直到生成结束（成功或异常）
  - 等待过程中，代码编辑区中的更新按钮和编辑框也必须被禁用

### 2. 代码编辑区

- 以标签形式切换显示业务模型定义和 UI 页面。其中，UI 页面根据 <page> 上的
  displayName 作为页面标签名，有多少个 <page> 就有多少个页面标签
- 在业务模型定义标签下可以在代码编辑和模型设计两种模式间自由切换。
  代码编辑模式显示的是生成的业务模型定义的 xml 内容，模型设计则负责显示模型间的关联关系
- 在各个 UI 页面标签下都可以在代码编辑和效果预览两种模式间自由切换。
  代码编辑模式显示的是生成的页面组件代码，效果预览则是显示编译该页面组件代码后的 HTML 展示效果
- 在编辑模式下提供更新按钮，由用户自行确定是否更新修改内容

注意，在各个标签的编辑模式下，**必须明显提醒用户**编辑结果将在 AI 重新生成后被覆盖，
建议其优先通过调整或细化需求后由 AI 自动生成，直到再也无法得到满意的 AI 生成结果为止。

### 3. 版本发布

- 点击发布按钮后弹出版本发布说明窗口，完成填写后才能确认发布
