## **一、核心规范**

- **设计**：移动优先、响应式布局
- **图标**：优先使用 svg 图标，若无合适图标，则自行绘制 svg 图标
- **组件**：优先使用框架生态中的组件，**禁止使用 Web 原生组件**，若无合适组件，则自行编写满足功能需求的组件
- **数据管理**：在非特别说明的情况下，缺省为主要业务模型设计增删改查功能以及配套的编辑、查看表单和数据列表。
  在数据列表上支持批量删除，新增表单支持保存成功后继续添加新数据
- **风格**：以醒目、清晰、简洁、直接为界面和功能的第一设计原则
- **编码**：清晰、简洁、明了
- **模块**：仅导入实际使用到的 ES 模块，**禁止导入无关和未使用的 ES 模块**

- 在描述说明、显示名称等文本内容中的中英文符号之间**必须添加空格**，但**中文标点和英文符号之间不能加空格**
- 使用声明式响应式编程风格，保持逻辑层与 UI 层分离
- 所有逻辑、自定义组件均在当前页面内完成，**禁止引入非框架以外的模块**，**禁止拆分为多个模块**

## **二、核心框架**

- **语言**：ES6 (ECMAScript 2015)
- **数据响应式**：Vue 3
- **图标库**：Lucide Vue Next（导入包名为 lucide-vue-next）
- **组件库**：Naive UI（导入包名为 naive-ui）
- **样式库**：Tailwind CSS
- **数据可视化**：Apache ECharts（导入报名为 echarts） + Vue ECharts（导入包名为 vue-echarts）
- **代码高亮**：highlight.js（导入包名为 highlight.js）

## **三、数据类型与组件**

- 自动根据业务模型结构及其属性类型确定组件的布局
- 根据业务模型属性的类型、可新增性、可更新性、虚实性、开放性等决定其在新增、编辑、查看表单中所采用的组件：
  - 虚属性始终不可编辑，为只读状态
  - 不可新增的属性不出现在新增表单中
  - 不可更新的属性在编辑表单中为只读的
  - 非开放的属性没有可回显值，若其为可更新的，则可以填写新值，并根据业务性质确定是否采用密码输入框。
    在查看表单中则需将其**标注为私密**
- 关联字典的属性采用下拉组件，且下拉组件的数据来自于对应的字典数据
- 在建立一对一或一对多关联时，对目标端的数据采用列表弹出窗口形式展示，并根据业务需求启用单选或多选

## **四、页面定义 <page>**

- 所有功能均只在**单个页面**内实现
- 若存在可复用组件，或者页面中的不同部分必须做作用域隔离时，可以在标签 <component> 中将其定义为独立的 vue 组件，
  再在 <page> 中引入：
  ```js
  import ComponentA from './components/ComponentA.vue';
  ```
- 生成的页面代码（page-code）和组件代码（component-code）**必须放在 XML CDATA 块中**
